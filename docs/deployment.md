# Deployment runbook

$0-budget topology — see ADR-0003 for why:

| Component | Host | Free-tier limits that matter |
|---|---|---|
| Postgres+PostGIS | **Neon** | 0.5 GB, compute suspends after 5 min idle (pool handles it) |
| API (uvicorn) | **Render** web service | sleeps on idle → cold start ~30–60 s; 750 h/mo |
| Web (Vite build) | **Cloudflare Pages** | static, unlimited bandwidth |
| Ingestion | **GitHub Actions cron** | best-effort timing; auto-disabled after 60 d repo inactivity |

**Never** use Render's free Postgres — it is deleted after 30 days.

## 1. Neon (database)

1. Create a project at neon.com (Postgres 16+, any region) — no card needed.
2. Enable PostGIS:
   ```sql
   CREATE EXTENSION IF NOT EXISTS postgis;
   ```
3. Copy the **pooled** connection string (`postgresql://…-pooler…`).
4. Migrate from a local checkout:
   ```sh
   cd backend
   EM_DATABASE_URL='postgresql://…neon.tech/…?sslmode=require' \
     uv run python -m app.db.migrate
   ```

## 2. Render (API)

1. New → Blueprint → connect this repo — `render.yaml` provisions the web
   service (Docker runtime, `backend/` context, `/v1/health` check, free plan).
2. Set the two `sync: false` env vars in the dashboard:
   - `EM_DATABASE_URL` — the Neon pooled string.
   - `EM_CORS_ORIGINS` — JSON array with the Pages origin, e.g.
     `["https://earth-monitor.pages.dev"]`.
3. `EM_JWT_SECRET` is auto-generated by the blueprint. `EM_DEV_USER_EMAIL` stays
   empty — and prod ignores it either way.
4. First deploy takes a few minutes (Docker build). Note the service URL,
   e.g. `https://earth-monitor-api.onrender.com`.

Cold starts: free web services sleep after ~15 min idle; expect ~30–60 s on
the first request. For a snappier demo, a free external pinger
(e.g. cron-job.org, UptimeRobot) hitting `/v1/health` every 5–14 min keeps it
warm — optional, and worth its own thought if the app gets real users.

## 3. Cloudflare Pages (web)

1. Pages → Connect to Git → this repo:
   - Build command: `npm run build -w web`
   - Build output: `web/dist`
   - Root directory: leave unset (monorepo build needs workspace root).
2. Environment variable (Production):
   - `VITE_API_URL=https://earth-monitor-api.onrender.com` (no trailing slash).
3. Deploy. The SPA needs one redirect rule for client-side paths — this app is
   single-page so it is not strictly needed, but add `web/public/_redirects`
   (`/* /index.html 200`) if routes ever grow.

## 4. GitHub Actions (ingestion)

1. Repo → Settings → Secrets and variables → Actions → `DATABASE_URL` = the
   Neon pooled string.
2. `.github/workflows/ingest.yml` runs `python -m app.ingest --once` every 6 h
   (best-effort) and on manual dispatch. Watermarks make delays harmless.
3. First prod run does a 30-day backfill — expect a few minutes of COG reads.

## 5. Smoke-check the deploy

```sh
API=https://earth-monitor-api.onrender.com
curl $API/v1/health                       # {"status":"ok","db":"ok"}
curl -X POST $API/v1/auth/register -H 'content-type: application/json' \
  -d '{"email":"you@example.com","password":"a-real-password"}'
curl $API/v1/aois -H "authorization: Bearer <token>"   # [] for a fresh user
```

Then open the Pages URL — the auth screen should appear (tokenless probe gets
401 in prod), register, draw an AOI, and wait for the next cron sweep.

## Failure modes worth remembering

- **GH schedule disabled** after 60 days of repo inactivity → re-enable in
  Actions tab or push a commit.
- **Neon suspend** → first request after idle adds a few seconds; pooled conns
  are validated on checkout so stale sockets don't reach requests.
- **Render free bandwidth** is 5 GB/mo egress — tiles are the heavy endpoint;
  `Cache-Control: immutable` + CDN caching in front of Pages covers static
  assets, but tile PNGs egress through Render.
